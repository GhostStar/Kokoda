[English](../en/window-manager.md)

状态：2026-11-22 已实现首批 macOS 管理界面；Qt 仍使用现有选择器。下文描述完整目标方案，交付说明区分本次实现和后续工作。

## 参考与取舍

分析 WinBridge 提交 `bd19a74477bcc0bb2d2cfc4633d11b62eb409374` 的实际源码，未运行其 GUI，也未复制其代码或资源：

- [ManagerWindowController](https://github.com/WormW/winbridge/blob/bd19a74477bcc0bb2d2cfc4633d11b62eb409374/mac-client/Sources/WinBridgeCore/UI/ManagerWindowController.swift)：连接配置、运行窗口／启动应用两页、图标与进程副标题、逐行投射／脱离、连接状态驱动按钮。其管理页搜索框只在应用页显示，并非两页统一搜索。
- [QuickLauncherMatcher](https://github.com/WormW/winbridge/blob/bd19a74477bcc0bb2d2cfc4633d11b62eb409374/mac-client/Sources/WinBridgeCore/UI/QuickLauncherMatcher.swift) 与 [QuickLauncherWindowController](https://github.com/WormW/winbridge/blob/bd19a74477bcc0bb2d2cfc4633d11b62eb409374/mac-client/Sources/WinBridgeCore/UI/QuickLauncherWindowController.swift)：统一搜索窗口与应用，匹配程度结合已投射状态排序，上下选择、回车执行、Esc 退出。
- [AppState](https://github.com/WormW/winbridge/blob/bd19a74477bcc0bb2d2cfc4633d11b62eb409374/mac-client/Sources/WinBridgeCore/App/AppState.swift)：重复打开聚焦已有窗口、取消订阅、重连恢复、布局记录。布局键主要按进程名区分，恢复允许退回进程名匹配；Kokoda 不将这些条件用作窗口身份或授权依据。

采用列表直接操作、状态清晰、快捷搜索及恢复布局的思路。Kokoda 不沿用默认红叉关闭远端应用、关闭 TLS 的普通设置、完整桌面快捷入口或同进程任意窗口替代恢复。画质仍全局生效，尺寸模式仍逐窗口生效。文件传输继续暂缓；应用启动、音频、网络发现和唤醒不因本设计自动纳入本轮实现。

## 客户端管理窗口

默认进入窗口管理；未连接时先显示连接表单，连接后收起为主机摘要，避免每次选窗口都面对密码和技术参数。一个客户端同一时间仍只连接一台主机。

| 区域 | 内容与操作 |
|---|---|
| 连接摘要 | 主机别名／地址、未连接／连接中／已连接／重连中；按状态提供连接、取消、断开、停止重连。密码仅在需要认证时输入，不持久化。 |
| 全局工具栏 | 全局画质、连接设置；剪贴板、自适应分辨率和自动重连在设置中。诊断收纳实际 FPS、码率、尺寸和编码器，不把编码器名作为普通操作入口。 |
| 列表导航 | “可用窗口”“正在查看”，两页都可搜索；标签数量分别表示可列出的独立窗口和正在查看的独立窗口，不把弹层数量混入应用数量。 |
| 窗口行 | 获准应用图标（不可用时通用图标）、窗口标题、应用名、状态、主操作及更多菜单。分辨率／DPI 放详情；空标题使用应用名或“无标题窗口”，不直接隐藏。 |
| 状态区域 | 展示可操作的失败原因；区分未共享窗口、没有搜索结果、窗口已消失、只读、连接断开。不得显示未授权窗口数量或标题。 |

初版不添加“启动应用”页：运行窗口的授权目录与可启动应用目录是不同权限。后续只有主机明确提供获准应用及启动能力时才展示，不能直接向客户端暴露全部开始菜单程序。

“正在查看”以独立窗口为主行，可展开所属浮动／模态窗口；临时菜单和工具提示不进入常驻列表。行身份使用连接代次、会话及窗口代次，不使用标题、行号或 PID。应用名只是展示／搜索字段，不自动意味着同一组。目录暂不具备安全显示名、图标或角色时使用通用表示，不把完整可执行路径发送给客户端来凑字段。

搜索先匹配完整标题、前缀和子串，再考虑模糊匹配；同等匹配下优先正在查看、最近使用的结果。中文按原文匹配，拼音检索另行实现，不能把英文子序列搜索描述为拼音支持。刷新保留选择和滚动位置；选中身份消失则清除选择，不能让原行号指向的新窗口接受误操作。

## 查看状态与操作

| 当前状态 | 双击／回车／主按钮 | 其他行为 |
|---|---|---|
| 可用、未打开 | 打开窗口，进入“正在打开” | 只读也可打开；主机再次验证权限与身份。 |
| 正在打开 | 不重复发起，显示进度 | 失败后可重试；结束查看后迟到的成功不能重新弹窗。 |
| 正在显示 | 切换到此本地窗口 | 已存在窗口不得另建一份；原生激活受平台限制。 |
| 本地最小化／关闭 | 恢复／重新显示 | 保留原尺寸模式，不改变主机最小化或关闭状态。 |
| 被模态窗口阻挡 | 切换到已获准模态窗口 | 不绕过主机阻挡；模态窗口不可用时说明原因。 |
| 重连中 | 暂停打开和远端输入 | 清空旧画面，保留本地布局意图；停止重连始终可用。 |
| 目标消失／撤权 | 禁止重新打开旧身份 | 清除媒体和私有元数据；如需状态反馈仅显示无标题提示。 |

“关闭本地窗口”隐藏该窗口及其所属浮动后代，其他独立窗口继续；现有暂停消费语义不等于已释放主机采集。“结束查看此应用”释放整个应用会话及其媒体资源，不关闭主机应用。两种动作单独命名，不能统一叫“关闭”或“脱离”。当前只有会话级结束查看；本设计不假定已有逐成员取消订阅协议。

“跟随关联窗口”是客户端查看偏好，始终取主机授权范围的子集，不是“允许共享整个进程”。模态／必要所属对话框与可选同应用独立窗口应分别处理。新独立窗口用普通本地窗口；浮动／模态窗口归属于实际 owner；菜单不加标题栏。开关变化的实时增删需具备明确的协议和身份校验后才能启用，现有选择时范围选项不能伪装成热更新。

查看窗口保留“缩放画面／调整主机”模式；本地标题栏的关闭、最小化和最大化始终只在本地执行。列表上下文菜单提供切换、重新显示、尺寸模式和结束查看，不默认增加远端关闭入口。画面里的应用按钮仍通过已授权远端输入生效。

## 快捷窗口选择器与布局

提供菜单中的“查找窗口…”入口，Mac 使用 Command+K，Windows／Linux 使用 Ctrl+K；仅在管理窗口内默认绑定，避免截获远端应用自己的快捷键。未来系统级快捷键由用户配置，Wayland 不支持时保留菜单入口。

选择器复用同一授权目录、状态和动作模型。上下键选项、回车执行、Esc 退出，输入法正在组词时回车先交给输入法。它只检索当前获准窗口；断线清除目录，显示连接入口，不保留旧的私有标题。打开后将输入焦点交还目标查看窗口。不能用刷新列表来抢占搜索框焦点。

首批仅保留现有连接恢复中的本地布局。未来跨启动保存布局必须分主机、应用及窗口实例／明确布局槽位，不能只用进程名覆盖同应用多个窗口。主机身份没有可靠的持久标识时，不按 IP 自动恢复；不默认保存聊天标题、截图、密码或输入内容。恢复先认证并获取新授权目录，匹配不唯一则交由用户选择，不能自动退回第一个同名进程窗口。显示器移除时将窗口移回可见工作区，并遵循平台及现有等比缩放约束。

## 主机选取与授权管理

客户端列表回答“我要查看什么”，主机共享页回答“允许对方看到什么”。客户端收藏、打开、关联发现和布局恢复都不能修改主机策略。

主机页提供“仅指定窗口／全部应用窗口”两种范围，默认前者且空列表不共享。所有者可在本机运行窗口列表里选择一个窗口作为规则示例，随后明确选择程序路径条件、标题包含条件或两者组合，并显示最终匹配预览。选一个样本不等于只授权该瞬时 HWND：保存前应写明规则可能匹配未来窗口；未实现瞬时单窗授权时不提供误导性勾选按钮。

预览分开显示独立匹配和可继承的所属窗口；同 PID 的其他聊天不能因为选了一个聊天而自动获准。独立窗口仍须自己命中规则。预览中的路径仅在主机显示。提供预览刷新，标注检查时刻；实际目录和采集仍实时重验，预览不是永久授权凭证。

当前限制必须直接体现在 UI：指定范围仅供查看，规则修改需停止共享并重启。按钮使用“保存并重启共享”，有连接时说明会断开；保存失败保留草稿，取消不修改生效策略，不静默回退全部共享。未来实现受限控制和策略热更新后再调整能力及文案，不能提前显示可用的控制权限。

## 交付顺序与验收

1. 三端统一管理列表与状态动作：可用／正在查看、标题搜索、行内打开／切换／重新显示、结束查看、清晰空状态。保持现有传输和认证。
2. 将目录与查看状态投影、搜索和动作资格迁入 `crates/client`／`crates/app-model`，由 AppKit 和 Qt 渲染；共享合同与首批 UI 一起交付，避免平台各自定义“已打开”。主机安全元数据不足时先提供必要协议能力，不能靠客户端猜测补齐。
3. 复用模型做快捷选择器；补主机规则示例选择和预览。跨启动布局、应用启动及网络发现另行交付。

验收包含：相同进程两个独立窗口、同名标题、模态阻挡、附属窗口本地关闭后恢复、刷新时行重排、打开中断线／取消／撤权、只读范围、无标题窗口、连接代次更换和旧结果拒绝。快捷选择器检查中文组词、键盘导航、焦点返回和读屏状态；主机检查空规则、样本到规则的范围说明、重启失败不扩权。Mac、Windows、Linux X11／Wayland 使用同一行为合同；Wayland 不承诺程序强制置前和任意坐标定位。中英文键及说明同步更新。本次实现及验证的子集见下方交付说明。


## 首批 macOS 交付 — 2026-11-22

AppKit 管理界面已提供可收起的连接表单、全局画质、选项、“可用窗口／正在查看”两页、标题搜索及状态驱动的行内动作。双击、回车和行内按钮走同一选取路径。“查找窗口…”和仅在管理窗口生效的 Command+K 聚焦同一个搜索框，尚无独立快捷选择面板。

正在查看可展开所属浮动／模态窗口，临时菜单不进入常驻列表。重新显示只恢复目标及其所属后代，不恢复用户单独关闭的独立兄弟窗口；结束查看可以取消正在打开的会话并拒绝迟到的选取／窗口组响应。刷新按身份保持选择，断线／撤权清除目录元数据。选取前的协议只有 HWND／进程／线程，没有窗口代次：客户端跟踪已观察的实例，拒绝已观察到的消失／复用；最终选取验证仍由主机负责。

`crates/client::manager` 经现有 C ABI 提供共享搜索排序及状态／动作资格，合同位于 `tests/contracts/window-manager.json`。原生会话／目录投影仍位于 Mac 适配层，Qt 接入下一轮进行。目前搜索支持忽略大小写的完整标题、前缀和子串匹配，中文按原文匹配。模糊／拼音／最近使用排序、应用名和图标、行详情／更多菜单、独立快捷选择器、持久布局及主机规则选择器仍待开发。当前使用通用图标，空标题显示“应用窗口”；目录未知角色暂保留为可选行，选取后的窗口组提供权威角色。

验证覆盖共享合同、中英文隔离 AppKit 管理界面、本地化、多会话、恢复、窗口组、窗口管理、尺寸、输入及拖动回归。本轮未重新实测 Windows 联网或实体 GPU，详见[验证记录](validation.md)。


Windows 规则示例选择器和 Mac 局域网发现现已实现，见[发现与主机选取](discovery.md)。该进展替代首批 Mac 交付说明中“主机规则选择器待开发”的状态。

## 可辨识目录与筛选 — 2026-11-22

Mac 管理列表改为紧凑双行：标题、程序名、应用图标，另列窗口物理尺寸及显示缩放。普通行不再重复“可用窗口”，主机最小化单独标明；删除底部重复的打开按钮，双击、回车和行内操作仍共用身份校验路径。

搜索支持标题和程序名。“显示”默认选择应用窗口，还可选已最小化、全部（含辅助窗口）。默认排除 DWM 隐藏、工具、禁止激活、系统桌面及无标题无边框辅助窗口；普通无标题应用保留，用程序名区分。筛选仅影响本地列表，不改变主机授权。正在查看的辅助窗口仍可访问，临时菜单仍不进入常驻管理列表。

Windows 主机仅对**已授权目录**补充可选 `catalog` 字段：程序文件名、固定 32×32 非预乘 RGBA 图标（base64）、DPI、角色、辅助窗口标记及尺寸（最小化时使用恢复尺寸）。不发送完整程序路径、窗口类名或私人 owner 编号。图标从程序资源提取，不给可能卡死的应用发送窗口消息；缓存最多 128 项、60 秒，提取失败允许缺省。Mac 拒绝格式或长度不符的图标。旧主机仍可连接，使用通用图标及窗口编号；完整列表需两端同时更新。显示元数据不能替代窗口身份或授权。

共享搜索语义已补程序名；Qt 可以接收附加元数据，但本轮尚未将其选择器替换为 Mac 管理布局。
