# 窗口角色与远端窗口操作

[English](../en/window-management.md)

一个会话管理多个已授权应用窗口，可以跨核验过的进程实例。窗口角色与进程归属分开：同一进程可以有多个独立窗口，另一进程也可以创建所属浮动对话框。角色由主机描述，所有客户端保持其语义。

| 主机窗口角色 | 客户端展示 | 窗口操作 |
|---|---|---|
| 独立窗口 | 分别展示为原生窗口，参与正常窗口切换／任务栏 | 本地关闭／最小化／最大化／恢复；本地缩放或显式调整主机尺寸 |
| 浮动窗口 | 所属原生面板，不单独进入任务栏／正常窗口切换，跟随所属窗口 | 本地关闭和缩放，可选择已授权的主机尺寸调整，没有独立最小化入口 |
| 模态对话框 | 所属对话框，其被禁用的拥有者不能接收远端输入或主机窗口操作 | 操作可用对话框，直到 Windows 重新启用拥有者 |
| 临时浮层 | 菜单、下拉框、提示气泡保持无边框，不额外增加标题栏／任务栏项 | 原生远端输入，生命周期由主机控制 |

Windows／Linux 客户端按平台映射任务栏。macOS 保留一个 Kokoda Dock 应用图标，独立窗口使用普通原生窗口，所属／临时面板不进入窗口菜单。这是共享行为规范，不要求共用原生渲染代码；Windows／Linux 图形客户端仍待实现。

协商 `window_management` 能力后，每个成员增加 `presentation`，包含物理采集所在显示器的 DPI（`dpi`，旧主机回退 96）、角色、过滤后的 owner ID、启用／最小化／最大化状态，以及关闭／最小化／最大化／尺寸调整能力。根窗口只是会话锚点，不决定展示类型。独立成员不挂在根窗口下；浮动／模态／临时成员挂到实际已授权拥有者。非受限应用模式下，初始根窗口关闭时由仍存在的独立成员接替锚点；受限模式根窗口消失仍拒绝继续共享。远端几何及原生状态同步不得回发成用户操作。

客户端标题栏的关闭、最小化、最大化、恢复始终只作用于本地查看窗口，包括“调整主机窗口大小”模式。带边框窗口的本地关闭按钮始终可用，即使主机不允许关闭、父窗被模态对话框阻断或当前只读。远端画面内应用自己的按钮仍通过正常远端输入操作主机。关闭本地窗口同时隐藏所属子树、释放按键和拖动状态，其他独立窗口继续显示；快照和迟到视频不能让它重新弹出。通过窗口菜单“重新显示本地已关闭窗口”，或从目录再次打开该应用可恢复。关闭本地模态查看窗口不会关闭主机对话框或解除其父窗阻断，需要恢复该窗口后继续操作对话框。

每个带标题栏的查看窗口（包括浮动面板）都直接提供原生选择器：**缩放画面**（默认）或**调整主机**。窗口菜单保留相同入口及 50%～200% 显示比例。选择器只作用于它所属的窗口，切换后将键盘／输入法焦点交回画面。

本地缩放模式下，拖动任意边缘或角落会联动宽高，保持当前画面的比例，不拉伸，也不额外留白边。本地最大化按屏幕可用区域容纳的最大等比尺寸展示。源画面比例变化时，以新显示的帧为准调整本地画布，屏幕能容纳时保留宽度；原生窗口的亚点取整细缝用等比绘制覆盖。源窗口内部自带的空白仍属于画面内容。

**调整主机**允许独立改变宽高，仅在完整操作权限且目标已启用、可调整尺寸时开放。拖边框改变的是源窗口物理尺寸，不是显示器分辨率或系统缩放。切回本地缩放时立即贴合当前画面。权限或目标能力失效时自动回到本地缩放，禁用主机调整选项，并通过悬停提示说明原因。两种模式下客户端关闭／最小化／最大化／恢复始终只在本地处理；等待主机尺寸变更时，视频可能短暂保留旧比例。

100% 时，本地点数＝源物理像素 × 96 ÷ 主机显示器 DPI。例如 Windows 250% 缩放下宽 1200 像素的窗口，在 Mac 中宽 480 点。Mac 2× Retina 屏幕会为这 480 点请求 960 个视频像素，不会把主机尺寸请求再乘二。即使应用不感知 DPI，主机也上报显示器倍率，因为采集结果已经被 Windows 放大。新弹窗首次继承拥有者的逻辑显示比例，之后本地几何独立。这是界面尺寸归一化，不保证以厘米计的物理尺寸完全一致，也不能增加源画面没有的细节。

匹配成员的本地大小、模式和关闭状态在自动重连后保留；成员消失／代次替换、显式结束观看或断开连接会清除偏好。隐藏窗口保留解码器，最多扣留协议允许的在途帧反馈（目前两帧），恢复时再返还，防止迟到视频重新打开窗口或无限堆积。这会暂停传送，不销毁主机采集线程；不支持反馈的旧主机仍解码隐藏视频。“结束观看此应用”释放整组观看会话；结束观看和断开连接都不关闭远端应用。包括尺寸调整在内的每个远端操作仍由主机复查代次、范围、原生身份及启用状态。

`window_action` 包含会话、窗口 ID、代次令牌及 `action`（`close`、`minimize`、`maximize`、`restore`、`activate`、`resize`）。尺寸请求额外携带有界的物理可见窗口宽高、用于边缘锚定的可选 left/top 坐标和客户端修订号。Windows 将可见 DWM 边界换算为原生外框，遵守系统最小／最大跟踪尺寸，并允许应用约束最终结果。关闭使用 WM_CLOSE，窗口操作不模拟鼠标移动。可能阻塞的尺寸约束调用设置超时。异步原生调用只表示请求已提交，实际状态以之后的快照为准。

在调整主机尺寸模式下，拖边框时本地立即响应。开始时固定源像素与 Mac 显示点的比例（排除 Mac 标题栏）；Retina 倍率仅用于视频分辨率。AppKit 原生最大化也触发 live-resize 回调，平台包装须在回调前标记此动作仅属本地。约每 100 ms 合并发送最新尺寸，松手保留最终修订；拖动及待确认期间，旧几何快照和归组布局不得覆盖本地大小。最终响应后短暂等待实际几何稳定，再以主机结果校准。只有此模式才按主机尺寸变化调整本地大小；未变化快照不能撤销本地最大化／恢复。各窗口视频视口仍独立防抖；断线不重放尺寸手势。

发现只在主机进行。现有有界周期目录刷新发现新窗口，未来可用原生事件钩子降低轮询延迟。自动跟随核验过的 owner 链，以及相同可执行文件的后代进程实例（规范路径、PID、创建时间），进程树按有界频率刷新。同名文件、同厂商、共同祖先或点击后的时间接近均不足以加入。已观察的后代只有在原进程实例仍存在时才继续符合条件，不自动加入无关实例或外部浏览器。不同可执行文件的无 owner 辅助程序、通过代理唤起的已有进程，目前需单独选择，显式辅助程序家族配置留待后续。归组不授予共享权限：先过滤主机目录再归组，采集／输入继续复查；不向客户端发送私有标题或程序路径作为发现提示。

首版 Windows 分类依据原生 owner、APPWINDOW／TOOLWINDOW 样式、已知菜单／提示／下拉窗口类和拥有者禁用状态，不声称准确识别所有自定义 UI 工具包。未知的无 owner 顶层窗口作为独立窗口，普通所属窗口作为浮动窗口；自定义情况通过合成回归逐步完善。
