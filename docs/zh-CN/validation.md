## 未解决回归：快速跨窗口输入

迁移的原型在完成输入注入后回复，目标应用此时可能尚未处理这些输入。提交 Unicode 后立即激活另一应用，可能截断前一应用的文字。标准 Windows 文本框在文本变更事件里执行文件写入时可以复现。低层输入送达标记及前台激活调整均未解决，相关实验代码已撤回。

`tests/e2e/verify-windows-runtime.ps1 -StressRapidSwitch` 保留失败复现。普通模式等到测试窗口实际观察到文字后才切换应用；普通模式通过不能宣称修复快速切换。通用方案需要确保事件归属，避免无限期绑定输入队列、记录本地键盘内容或在确认不明时重放文字。

## 输入流水线与播放消费反馈 — 2026-11-21

macOS 42 项、Windows x64 56 项 Rust 测试全部通过。新增覆盖部分发送／997 重试、真实 TLS 视频写入阻塞时继续接收控制、桥接响应与穿插画面的顺序关联、每窗口在途额度、无效／重复反馈及保守恢复。Mac 原生测试覆盖未收到确认前连续发送 12 批有序输入、剪贴板屏障、后台 JSON／Base64 分片解析及输入边界、独立解码、解码阻塞期间控制响应、断线及旧结果拒绝。154 个中英文资源键保持一致。

真实密码认证的 Mac bridge → Parallels Windows 测试暂停一个合成弹窗的消费反馈：该窗口恰好停在两帧，另一个独立窗口在三秒内仍收到 63 帧。该负载下控制 ping 中位数／最大值为 2.40／4.11 ms；归还额度后继续播放。故意注入 80 ms 解码指标后，30 FPS 上限降至 22 FPS，恢复正常指标后回升至 24 FPS；实时切换 15 FPS 档位后所有成员均受新上限约束。这些注入值验证控制逻辑，不代表硬件解码速度。

后台 IPC 解析及两个并发解码任务下，四窗口原生测试在两秒事件跟踪模式中完成 26 次定时移动，跟踪及随后 0.4 秒恢复期间收到 54 帧弹窗画面，无重连、无位置回跳。强制终止测试 bridge 后，认证、消费反馈协商和四个窗口均自动恢复。真实 Windows 标准／自定义标题栏拖动、反向移动、重复采样、几何回报、越界文字选择和释放再次通过，最大实测位置误差为 0 像素。

以上是 Mac 与 Parallels Windows 虚拟机上的合成测试，不是物理 NVIDIA／AMD／Intel、广域网丢包或保证帧率的基准。保留 TCP/TLS/OPAQUE；每窗口两帧在途上限限制积压，但高 RTT 链路可能受吞吐限制。自适应始终低于全局档位上限，不改变分辨率。快速跨应用切换时的 Unicode 输入压力问题仍未关闭。需更新两端才能启用消费反馈。临时主机、窗口、凭据、任务及受限防火墙规则已删除，虚拟机已挂起；未操作用户现有 Mac 客户端。
